# Generated database documentation

The implemented schema is generated by **ERAlchemy 1.7.0**, pinned in the backend development dependency group. It is not added to the runtime image. Canonical artifacts are `docs/architecture/database-schema.md` (Mermaid ER) and `database-schema.dot`. The authored [data map](../architecture/database.md) explains ownership, phrase content and planned entities separately.

## Generate or check

Complete the disposable PostgreSQL configuration in [backend setup](backend-setup.md). From the repository root:

```sh
# Generate canonical text; optionally render a local SVG using Graphviz.
AION_TEST_DATABASE_URL_FILE="$PWD/.local/backend/database-url-host" \
  uv run --project apps/backend --locked python tools/export-database-diagram.py \
  --render-to .local/schema/database-schema.svg

# Fail if committed canonical files are stale; do not rewrite them.
AION_TEST_DATABASE_URL_FILE="$PWD/.local/backend/database-url-host" \
  uv run --project apps/backend --locked python tools/export-database-diagram.py --check
```

The generator creates a uniquely named `aion_docs_*` schema in the explicitly supplied disposable PostgreSQL database, applies every Alembic migration, reflects schema metadata and drops only that temporary schema in a `finally` block. It does not migrate, read rows from or drop the preview application's schema. Never point the test connection at production. After a killed process, inspect and remove only the identified abandoned temporary schema before reusing that disposable environment.

The input variable is the same explicit test connection used by integration checks; exactly one `AION_TEST_DATABASE_URL` or `AION_TEST_DATABASE_URL_FILE` must be supplied. Credentials are never written to artifacts or command output. No production credentials or schema upload service is required. The script removes ERAlchemy's external Mermaid image URL and normalizes its nullable relationship spelling to standard Mermaid ER symbols.

Open `docs/architecture/database-schema.md` in a Mermaid-capable Markdown viewer or GitHub. For an image, open `.local/schema/database-schema.svg` after running the generation command. Graphviz `dot` must be installed for SVG output; local rendering was checked with Graphviz 15.0.0. Rendering is optional for canonical text checks. SVG bytes are not compared across Graphviz/font/OS versions; canonical Markdown and DOT are compared exactly. No timestamp, temporary schema name or machine path is included in canonical output.

## CI and maintenance

`tools/check-backend.sh` includes the freshness check and real-PostgreSQL diagram tests. Backend CI runs on every PR/main push, installs Graphviz, renders the canonical DOT locally and retains the SVG as the `database-schema` artifact for 14 days. The render command repeats the freshness check. CI never automatically commits regenerated files. Hosted CI results exist only after the changed workflow runs.

For schema changes, regenerate and review the canonical artifacts with the migration; update the authored overview when meaning, retention or plans change. Model edits alone do not replace missing migrations. Existing integration checks continue to verify model/migration agreement. Keep the generator, ERAlchemy, SQLAlchemy and lockfile changes in the same review if output changes.

An ER diagram omits some indexes, defaults, checks, unique constraints and policy behavior. ERAlchemy's relationship multiplicity does not capture every uniqueness constraint: `verification_mail.challenge_id` is unique, so at most one verification-mail row exists per challenge even if the diagram displays the generic foreign-key collection. Exact behavior remains in migrations/models/tests and the authored overview. Migration bookkeeping `alembic_version` is excluded. This is revision-based documentation, not continuous production drift monitoring.

## Local verification

The generator was run against a fresh temporary schema and then checked for deterministic output. Integration tests verify that the migrated schema matches committed artifacts and that adding a synthetic database column changes both outputs without editing ORM models. A deliberately stale copy was also checked to ensure nonzero exit and automatic temporary-schema cleanup. Graphviz rendered the SVG successfully. Full local backend checks passed with 41 tests, including four schema-documentation tests, plus Ruff/mypy and OpenAPI/schema freshness. Generated Mermaid was independently parsed with Mermaid 12.2.0 in a temporary validation environment; this parser is not a runtime dependency. Public-boundary/secret and diff-whitespace checks passed. Hosted CI has not run for this uncommitted working tree. These checks do not change the deployed app or establish a production account release.
